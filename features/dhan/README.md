# Dhan Integration (Phase 1A)

This module provides a secure, server-side data layer wrapping the Dhan HQ API for fetching historical daily OHLC data. 
It includes an in-memory rate limiter that respects Dhan's documented rate limits and a local caching layer via Supabase.

## Architecture & Auth Flow

1. **Server-Side Only**: This module accesses sensitive tokens and must NEVER be imported in a client component. We enforce this using the `server-only` package.
2. **Authentication**: The module authenticates with Dhan using a single set of API credentials supplied via server environment variables:
   - `DHAN_CLIENT_ID`
   - `DHAN_ACCESS_TOKEN`
3. **Single-Account Credentials**: 
   > ⚠️ **IMPORTANT FLAG**: This integration currently uses a **single account's credentials** (not per-user broker linking). The `access-token` is generated by logging into [web.dhan.co](https://web.dhan.co) and accessing the "Access DhanHQ APIs" section under your profile. 
   > Serving other users' data through this same key would require per-user broker OAuth instead. This is a significant compliance question (acting as a data vendor vs. providing personal analytics), not just a code change.

## Key Files

- `dhanClient.ts`: Main client exposing `getHistoricalDaily` and `refreshLatestBar`. Handles caching and request throttling.
- `errors.ts`: Custom error types for API failures, rate limiting, and validation.
- `/scripts/syncDhanSymbols.ts`: Script to download and parse Dhan's instrument master CSV, seeding the `symbols` table.
- `/scripts/fetchSampleData.ts`: E2E test script to download and cache 2 years of data for a few sample symbols.

## Caching Strategy

The `getHistoricalDaily` method automatically checks the `price_cache` table in Supabase. It calculates missing gaps and only fetches the needed contiguous chunk from Dhan, then upserts the new bars back into the cache before returning the combined dataset.
